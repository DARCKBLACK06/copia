3.3	TÉCNICAS Y HERRAMIENTAS UTILIZADAS PARA EL DESARROLLO DEL    PROYECTO
4	Durante el desarrollo del proyecto fue necesario apoyarse en diversas herramientas tecnológicas que facilitaron tanto la programación del microcontrolador como la creación e implementación del sistema web. Las siguientes herramientas fueron seleccionadas no solo por su capacidad técnica, sino también por su compatibilidad entre sí, su facilidad de uso y su eficiencia para resolver las necesidades reales que se presentaron.
5	________________________________________
6	Visual Studio Code
7	Visual Studio Code fue el entorno principal en el que se desarrolló la mayor parte del código, tanto del lado cliente como del lado servidor. Se eligió por ser un editor muy completo, liviano y compatible con muchas extensiones útiles. Por ejemplo, con extensiones como Firebase Tools, Live Server y Prettier, pudimos organizar mejor el trabajo, visualizar en vivo los cambios y mantener el código ordenado. Además, su integración con Git nos permitió versionar nuestro trabajo desde el mismo editor, algo que resultó práctico en varias etapas del desarrollo.
8	________________________________________
9	Node.js
10	Node.js se utilizó para gestionar ciertas funciones del backend y facilitar las conexiones entre el ESP32 y la base de datos en la nube. Gracias a Node.js pudimos trabajar con librerías como firebase-admin para validar información en tiempo real. Esto fue especialmente útil para funciones como verificar si un usuario había hecho su pago antes de permitirle el acceso a la oficina. Lo que más ayudó de esta herramienta fue su capacidad para manejar múltiples procesos de manera asíncrona, lo cual evitó retrasos o bloqueos en el sistema.
11	________________________________________
12	Firebase
13	Firebase fue una de las plataformas más importantes del proyecto, ya que resolvió muchas necesidades a la vez. Utilizamos Realtime Database para registrar los datos de sensores como humedad, temperatura, gas, entre otros, lo que nos permitió leer en tiempo real desde el panel administrativo. También usamos Firestore para manejar la parte de usuarios, contratos y accesos. Además, gracias a Firebase Authentication, logramos implementar un sistema de login seguro sin tener que crear uno desde cero. Finalmente, Firebase Hosting nos sirvió para subir la página completa sin necesidad de configurar un servidor externo. Firebase nos permitió concentrarnos en lo funcional sin perder tiempo en instalaciones complicadas.
14	________________________________________
15	JavaScript
16	JavaScript fue el lenguaje base para toda la lógica del sistema web. Desde manipular el DOM para mostrar datos en pantalla, hasta leer datos de Firebase, todo se logró con este lenguaje. Por ejemplo, usamos JavaScript para mostrar gráficas que se actualizan en tiempo real cuando cambian los valores de los sensores, lo que permitió al administrador tener una vista clara del estado ambiental de las oficinas.
17	________________________________________
18	Bootstrap
19	Bootstrap nos ayudó a construir la interfaz gráfica del sistema sin tener que preocuparnos demasiado por los estilos desde cero. Con sus clases predefinidas logramos tener un diseño visual limpio, ordenado y compatible con distintos dispositivos. Algo importante fue que nos permitió organizar de forma clara las tarjetas informativas, botones de acceso, menús desplegables y modales donde se mostraban las gráficas.
20	________________________________________
21	Chart.js
22	Para mostrar los datos de los sensores en tiempo real de forma visual, usamos Chart.js. Esta herramienta nos permitió crear gráficas circulares (tipo dona) y de líneas para representar variables como temperatura, humedad, flujo de agua, entre otras. Lo que más nos ayudó de esta biblioteca fue que se integró fácilmente con Firebase, por lo que cada vez que los datos cambiaban en la base de datos, las gráficas se actualizaban automáticamente sin necesidad de recargar la página.
23	________________________________________
24	Arduino IDE
25	El Arduino IDE fue fundamental para programar el microcontrolador ESP32. Desde aquí escribimos el código que permite que el dispositivo lea los sensores conectados y se comunique con Firebase a través de Wi-Fi. También desde aquí se definieron los pines digitales, las configuraciones de conexión, y se hizo la depuración del código con pruebas en físico. Su interfaz sencilla y compatibilidad con librerías externas facilitaron mucho el trabajo.
26	________________________________________
27	Git y GitHub
28	Para evitar perder el trabajo o confundir versiones del sistema, utilizamos Git como herramienta de control de versiones. Esto nos permitió guardar diferentes estados del código e incluso regresar a versiones anteriores cuando algo salía mal. GitHub nos sirvió como respaldo en línea y como espacio colaborativo para trabajar desde diferentes computadoras sin perder sincronía. Esto fue clave especialmente cuando teníamos que probar cosas nuevas sin dañar el sistema principal.
